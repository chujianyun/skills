# 请求限流

## 限流机制 {#overview}

词元跳动在两个维度对请求频率进行限制（RPM，即每分钟请求数），以保障平台稳定性和公平使用：

| 维度 | 默认限制 | 说明 |
|---|---|---|
| 用户维度 | 500 RPM | 同一用户所有 API Key 的请求总和 |
| API Key 维度 | 500 RPM | 单个 API Key 的请求数 |

两个维度的限流同时生效，即一个请求需要同时满足用户维度和 Key 维度的限制才能通过。

## 查看当前限制 {#check-limits}

你可以在以下页面查看自己的限流配置：

- **用户 RPM**：访问 [「个人信息」](https://tokendance.space/settings) 或 [「额度管理」](https://tokendance.space/credits) 页面查看
- **API Key RPM**：访问 [「API 密钥」](https://tokendance.space/keys) 页面查看每个 Key 的限制

::: note
如有更高的频率需求，请联系官方人员调整限额。
:::

## 触发限流时的响应 {#rate-limit-response}

当请求触发平台限流时，API 会返回 HTTP 429 状态码。建议在客户端实现指数退避重试策略来处理此类响应。

## 供应商限流 {#provider-rate-limits}

除了词元跳动自身的限流外，在流式输出（stream）模式下，如果当前模型的所有供应商均因资源不足而返回限流错误，你可能会收到来自上游供应商的原始限流信息。这是因为词元跳动会忠实透传最后一个供应商返回的异常。

这种情况通常发生在热门模型的高峰时段，所有供应商的并发资源都已耗尽。

::: warning
供应商限流与词元跳动的平台限流无关，它表示上游模型服务商的资源暂时不足。当遇到此类错误时，建议稍后重试，或考虑使用 [模型降级](%E6%A8%A1%E5%9E%8B%E9%99%8D%E7%BA%A7.md) 功能配置备选模型。
:::
