# 应用归因

TokenDance 仅使用 App URL 进行应用归因，App URL 是应用归因的唯一要素。它既可以记录在 API Key 上，也可以
随每次模型请求传递。

::: tip
App URL 不要求是应用的官方网站，也不要求能够被访问。它只需要采用 URL 形式，并且对同一个应用保持唯一、
稳定。Web 应用通常使用自己的站点 URL；桌面客户端、CLI 等本地应用可以自行约定一个不会与其他应用冲突的
URL，例如 `app://example-desktop`。
:::

## 应用归因的两个维度 {#dimensions}

| 维度 | 传递方式 | 表示什么 |
|---|---|---|
| API Key | OAuth 授权参数 `app_url` | 写入 Key 的 App URL，后续使用该 Key 的调用会自动继承 |
| 请求 | `X-App-URL` 请求头 | 显式声明这一次调用实际来自哪个 App URL |

两个维度使用的是同一个 App URL，不是两套标识。请求维度存在时优先使用 `X-App-URL`；请求维度缺失时，
调用会继承 API Key 上的 App URL。OAuth `app_url` 的传递方式见
[OAuth 式 API Key 授权](../%E8%AE%BF%E9%97%AE%E4%B8%8E%E8%AE%A4%E8%AF%81/OAuth%20%E5%BC%8F%20API%20Key%20%E6%8E%88%E6%9D%83.md#authorize)。

### 示例 {#dimension-examples}

| 产品形态 | OAuth `app_url`（API Key 维度） | `X-App-URL`（请求维度） |
|---|---|---|
| Web 应用 | `https://example.com/app` | `https://example.com/app` |
| 桌面客户端 | `app://example-desktop` | `app://example-desktop` |
| CLI | `app://example-cli` | `app://example-cli` |

如果 Key 不是通过 OAuth 式授权创建的，它就没有 API Key 维度的 App URL；应用仍然可以在每次请求中使用
`X-App-URL` 声明请求维度。

## 请求头 {#headers}

| 请求头 | 说明 | 示例 |
|---|---|---|
| X-App-URL | 请求维度的 App URL | https://myapp.com |
| X-Site-URL | 旧客户端兼容请求头；仅在没有 X-App-URL 时读取 | https://myapp.com |

新接入只应使用 `X-App-URL`。`X-Site-URL` 仅用于兼容存量客户端，后续不要继续新增依赖。
除上述两个请求头外，其他请求头均不参与应用归因。

请求头不是每次都必须传：如果 OAuth 创建的 Key 只会用于当前应用，可以直接使用 API Key 维度；如果同一个 Key
可能被多个应用使用，或者需要明确单次调用的实际来源，则应在每次请求中传递 `X-App-URL`。

## 使用示例 {#examples}

:::group

```python title="Python (OpenAI)"
from openai import OpenAI

client = OpenAI(
    api_key="YOUR_KEY",
    base_url="https://tokendance.space/gateway/v1",
)

response = client.chat.completions.create(
    extra_headers={
        "X-App-URL": "https://myapp.com",
    },
    model="deepseek-v3.2",
    messages=[{"role": "user", "content": "Hello!"}]
)
```

```javascript title="Node.js (OpenAI)"
import OpenAI from 'openai';

const client = new OpenAI({
  apiKey: 'YOUR_KEY',
  baseURL: 'https://tokendance.space/gateway/v1',
  defaultHeaders: {
    'X-App-URL': 'https://myapp.com',
  },
});

const response = await client.chat.completions.create({
  model: 'deepseek-v3.2',
  messages: [{ role: 'user', content: 'Hello!' }],
});
```

```bash title="cURL"
curl https://tokendance.space/gateway/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_KEY" \
  -H "X-App-URL: https://myapp.com" \
  -d '{
    "model": "deepseek-v3.2",
    "messages": [{"role": "user", "content": "Hello!"}]
  }'
```

:::

## 最佳实践 {#best-practices}

- Web 应用优先使用自己的稳定站点 URL，例如 `https://myapp.com`
- 本地应用可以自行约定稳定且唯一的 URL，例如 `app://example-desktop`，无需为它专门部署网站
- 同一个应用在 OAuth `app_url` 和请求 `X-App-URL` 中使用完全相同的值，并避免后续随意变更
- 如果一个 API Key 会跨应用使用，每次请求都传递 `X-App-URL`，避免继承错误的 API Key 归因
- 不要把用户 ID、API Key 或其他敏感信息放入 App URL

::: note
只有最终得到 App URL 的调用才会归属于对应应用：请求维度优先，没有请求维度时回退 API Key 维度。
:::
