# 图片编辑执行指南

## 工具与输入

需要能够查看图片并结合多张参考图编辑原照片的工具。Codex 中优先用内置 `view_image` 和 `image_gen`，以当前工具实际名称、参数和限制为准。

1. 检查图片查看和编辑能力是否可调用；内置工具不需要安装 Python 包或另配 API 密钥。
2. 无查看能力时不能猜人物位置；无编辑能力时可给出待处理清单，但明确尚未打码。需要安装或启用支持图像编辑的工具时，说明所缺能力，请用户启用；不捏造通用安装命令。
3. 用户指定仅本地时停止云端编辑。只有另行明确授权本地脚本／其他实现方式后才采用相应方案；本技能没有附带本地人脸检测或贴图程序。
4. 本地原图和头像先逐一查看。若格式不受支持，说明具体文件；经当前环境允许的转换流程准备副本后再处理，不能直接改后缀冒充转换。
5. 工具支持 `referenced_image_paths` 时，使用当前实际绝对路径，原图排第一，后面是所选头像。目标中含无本地路径的对话图片时，按工具约定使用能覆盖全部目标的最少近期图片数；不要同时提供两种引用方式。
6. 输入数量超过工具上限时，按其实际能力拆成小步编辑，每一步都对照原图，避免多次生成导致画面漂移。不能静默丢弃头像或把另一张照片当成参考。

内置工具不可用，不自动改用外部 API 或上传到在线打码网站。额外付费调用需已有具体授权；不要让用户把密钥粘贴到对话中。

## 单张照片编辑提示词模板

实际调用前填好位置、素材和跳过对象，不把未填写模板直接提交给工具。

```text
任务：在这张照片上用所提供的表情头像做隐私遮挡。
输入 1 是唯一要编辑的原照片；其余输入仅是供插入的头像素材。

保留人物：{本图内明确位置、衣着或用户圈选的描述}。
需要遮挡的人物与素材：
{逐个列出：本图内位置、脸部范围、对应第几个输入头像}。
必须跳过的其他人物：{明显侧脸与背影的位置}。

只在指定的待遮挡脸部区域叠加对应头像。把头像从素材的实色
棋盘格背景中提取出来，不粘贴矩形背景，不把棋盘格带进照片。
头像内部完全不透明，以完整头像轮廓盖住目标的眉眼、鼻子、嘴、
下巴与脸部可辨认边缘，适当放大，圆形边缘不可漏出五官。
不要遮到保留人物的脸。眼镜、闭眼也不能成为遗漏正脸的理由。

保留原照片画面边界、构图、方向和比例，尽量维持原尺寸。
保留人物的面部、表情、发型、身体和衣服保持原样；其他人物
的身体、衣着、周围物体、背景和原有文字也保持原样。
不要换脸、美颜、改光线、补画人物、裁切、拼图或添加文字。
输出这一张照片的完整编辑结果。
```

若用户的圈线只是定位标记且另有干净原图，以干净原图作为编辑目标，圈选图只辅助定位；只有带标记版本时说明情况，不能声称获得未标记原件。

## 逐张验收

原图用于比对，不另生成可能被误发的“原图＋成品”拼图。

- **人物正确**：逐一对照用户定位，确认保留人物未被误遮；检查远处、画面边缘的人脸是否遗漏。
- **规则正确**：正脸与近正脸已盖住，明显侧脸和背影跳过；输出人数以人工逐张核对结果为准，不能凭工具自述填写。
- **覆盖完整**：按原尺寸查看每个遮挡边缘；没有透出的眉眼、鼻口、下巴，也没有棋盘格或明显白色方框。
- **画面保持**：查看保留人物、背景文字、物体和画面边界；工具改动非目标内容时修正，仍不能满足就标为待确认。
- **文件可用**：确认输出存在、可以打开、格式正确，记录实际尺寸；不把预览截图当原尺寸成品。
- **元数据**：有元数据检查工具时核查 EXIF／GPS／嵌入缩略图，另存发布副本时移除这些附加信息；可保留显示所需色彩信息。先应用方向信息再清理方向标签。没有检查工具则如实标明未核验，不能保证“已清除定位”。不为了检查而把照片上传到新服务。

结果只通过可见内容核对，不等于像素级保真。用户要求严格原像素、特定分辨率或只在本机处理而当前工具无法满足时，应在处理前说明，不在交付时才隐瞒降级。

## 批量和失败处理

每张照片独立记录“待定位／可编辑／待修正／已检查／失败”。一张缺信息不阻止其他明确照片；仅对失败项重试，已经检查通过的照片不反复生成。

连续两轮针对性修正仍有误遮、漏脸、背景漂移或素材方框时，停止该张生成并说明问题。调用失败、输入不可读或无实际输出不算完成；未经检查的结果标为待确认。

批量交付示例字段：文件、保留人物、遮挡人数、跳过侧脸／背影人数、状态。用户需要压缩包时仅放已检查的发布副本，排除原图、定位截图、提示词和本地绝对路径清单。
