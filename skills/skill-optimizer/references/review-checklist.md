# Skill 审查清单

按本次改动选相关部分；不要求每次穷举。可将结论标为通过、存疑、不通过或不适用，并附具体依据。缺少 README、脚本、索引或模式标签本身不构成缺陷。

## 1. 触发精度

- 目录名与 frontmatter `name` 是否一致，字段是否满足当前仓库和运行平台要求？
- `description` 是否以简短、靠前的信息表达做什么及何时使用？
- 是否堆积同义词、执行细节或“任何相关任务都必须使用”等过宽触发条件？
- 是否能区分相邻技能和执行业务任务的请求？有重叠时才补必要的非适用场景。
- 若运行时截短描述，关键适用条件是否仍可见？未知截断机制时不凭空规定字符阈值。

## 2. 指令必要性

对可疑规则逐项询问：

- 它提供什么任务特有信息？是否重复模型常识、其他文件或上层规则？
- 它防止什么已知失败？没有证据时区分推测与事实。
- 删除它会失去哪项保障？存在保障损失时，能否缩小适用条件而非直接删除？
- 它应是硬约束、默认建议，还是可选方法？

给出保留、合并、条件化、移至按需资料或删除的建议。不以删字数量作为优化目标，也不为证明价值强行改写有效内容。

## 3. 工作流与授权

- 是否定义输入、目标产物、必要依赖顺序和可判断的完成条件？
- 是否把简单任务强制展开为完整清单、固定模板或多轮提问？
- 是否同时识别“仅建议”“明确授权实施”和“新风险或越界”？
- 是否复用对话中对相同操作的有效授权，而非反复等待口令？
- 删除、覆盖、重启、部署、外部写入、付费或凭据变更是否核实具体授权？
- 优化目标技能与执行其中的业务操作是否明确区分？
- 缺输入、命令失败、鉴权失败、空结果等实际相关异常是否有降级或停止条件？
- 是否会在首版完成后过早停止，或在检查通过后无限扩大工作？

## 4. 加载成本与资源

- 根文档能否指导当前任务只读取必要资料？每个链接是否有读取条件？
- 移入 references 的内容是否仍被要求每次全读，或与正文重复？
- 局部调整是否被要求阅读全仓库地图、所有同级技能或无关长文？
- 文件拆分是否减少实际无关加载，而非仅让入口看起来更短？
- 脚本、模板和索引是否解决稳定性或定位困难，有无使用成本大于收益的包装？
- README 是否有实际人类读者需求或仓库要求？已有 README 是否与执行规范互补？
- 是否存在职责混杂或不必要的技能拆分？仅检查与本轮有关的相邻技能。

## 5. 依赖与安全

- 必需工具是否说明安装、验证和缺失时的降级或停止方式？
- 平台特定、模型特定及可能过时的依赖规则是否标明适用范围？
- 是否存在明文密钥、令牌、Cookie、私有地址或机器特定配置？只报告类型与位置。
- 公开分发前是否妥善处理敏感内容？不能用一句风险提示代替处理。
- 安装依赖、调用目标脚本或业务服务是否产生未经授权的副作用？
- 高风险步骤的边界是否必要且具体，是否误阻止已授权的低风险工作？

## 6. 结果与行为验证

先区分证据层级：

- **静态审查**：检查文件、引用和规则，不能证明模型实际行为。
- **场景推演**：用请求逐步解释预期分支，帮助发现矛盾，不等同于模型运行测试。
- **实际运行**：在可用且已授权的环境中向模型提交场景，记录实际行为与预期差异；业务副作用用隔离环境或模拟工具。

按改动风险选少量代表场景，不机械要求全量运行：

| 场景 | 对 skill-optimizer 的示例输入 | 预期行为 |
|---|---|---|
| 应触发 | “检查这个 Skill 的触发条件” | 定位并审查目标的相关部分 |
| 不应触发 | “用下载技能下载这段视频” | 不因提到技能就启动优化 |
| 仅建议 | “大概怎么优化” | 给诊断和计划，不修改 |
| 已授权实施 | 已讨论方案后说“按这个思路改好并验证” | 修改范围内文件，完成必要验证，不重复问授权 |
| 授权不明确 | 方案后只说“有道理” | 不据此开始修改 |
| 越界操作 | 本轮仅授权改触发词，却发现应删除另一个技能 | 另列建议，不擅自删除 |
| 依赖缺失 | “验证技能”，但验证器不可用 | 完成可做检查，明确哪些未验证及原因 |
| 检查失败 | 本轮改动导致引用失效 | 修复并复查受影响项；无法修复时报告阻塞 |
| 已完成 | 范围内修改和必要检查已通过 | 完成已授权交付步骤并汇报，不无限追加测试 |

验证触发时只向路由阶段提供实际会看到的名称和描述，不预先强制加载完整技能。验证工作流时再加载技能正文。已授权场景应带上必要的前序对话。

需证明改进时，在相同任务、模型、工具权限和判定标准下比较修改前后。记录场景输入、版本、预期、实际结果和未验证项；失败时调整相关规则并复查，不事后更改标准以掩盖退化。未进行真实测试或测量时不宣称性能提升。

## 7. 优先级

1. 先处理敏感信息、越权、触发失败、流程错误和规则冲突。
2. 再处理完成条件缺失、授权导致的错误停顿、异常策略缺失、依赖问题及无关加载。
3. 最后按收益决定文档组织、措辞和示例调整；允许不改动。
