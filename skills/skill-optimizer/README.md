# skill-optimizer

审查并优化已有 Skill，帮助它用尽量少、确实有效的指令稳定完成任务。既查缺失的保障，也识别冗余规则、过宽触发和不必要的停顿；有效的内容可以保留原样。

## 适用场景

- Skill 经常误触发，或和其他技能边界重叠
- 简单请求也读取大量资料、展开完整流程或反复确认
- 需要检查依赖、失败处理、安全边界和完成标准
- 想精简或重构技能，并了解如何验证修改效果

本技能审查技能本身，不负责执行被审查技能的业务任务。

## 如何使用

- “大概怎么优化这个 Skill”：获得按优先级（P0/P1/P2）排序的问题、逐项修改建议和设计模式判断。
- “只检查 description”：围绕触发条件做局部审查。
- 讨论方案后说“按这个思路改好并验证”：完成范围内修改和必要校验，不重复询问已有授权。

输出统一按“问题（P0/P1/P2）→ 修改建议 → 设计模式判断”组织：局部修改只写一到三项但保留优先级标签，复杂重构再展开依赖、风险和处理顺序。问题会说明涉及 Tool Wrapper、Generator、Reviewer、Inversion、Pipeline 中的哪个模式及偏离所在；与模式无关时直接写明。README、索引、模板与脚本根据实际需要及仓库要求添加。

每个环节结束都会交代你现在是否需要操作，以及下一步是等待核对、自动继续、受阻还是本轮已完成。需要核对时会给出具体方案和确认后的动作；已授权的修改会继续推进，未运行的回归评测也会明确说明。

## 验证与边界

验证结果会区分静态审查、场景推演和实际运行。没有真实测试就不声称触发率或完成率提高，也不承诺未经验证的跨模型效果。

授权按完整对话和适用仓库规则判断。只要建议时保持只读；已授权实施时持续完成必要步骤。新出现的高风险或范围外操作需核实具体授权，技能优化不自动授权其中的业务操作。敏感信息不会在报告中回显。

## 设计依据

融合既有技能设计经验与 OpenAI 的 [Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)。采用按需加载、精确触发与重新评估旧约束的思路，保持技能对不同模型的通用性。
