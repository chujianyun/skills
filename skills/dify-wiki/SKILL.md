# Dify Wiki

以随 Skill 打包的中文官方文档为依据回答 Dify 问题。覆盖用户指定的 Cloud 顶部「使用」「学习」「开发者资源」，包括共享教程、CLI、插件开发和 API；自部署产品的独立部署文档不在本快照内。

## 检索与回答

1. 从当前 `SKILL.md` 定位 Skill 根目录。提取 2–5 个关键词，用空格分开，保留节点名、接口路径和报错中的产品术语。
2. 用 Python 3.10+ 标准库运行本地全文检索：

   ```bash
   python3 <skill-root>/scripts/search_docs.py "知识检索 召回"
   python3 <skill-root>/scripts/search_docs.py "streaming 流式" --prefix "开发者资源/API"
   ```

   按问题选择前缀：

   | 问题 | `--prefix` |
   | --- | --- |
   | 工作流、节点、知识库、发布、监控、工作空间 | `使用` |
   | 入门、核心概念、工作流 101、实战教程 | `学习` |
   | difyctl 安装、登录、命令、应用调试 | `开发者资源/CLI` |
   | 模型、工具、触发器、数据源插件与 Marketplace | `开发者资源/插件开发` |
   | 应用调用、SSE、知识库接口、参数和响应 | `开发者资源/API` |

3. 读取排名靠前且互补的 1–3 篇文档；复杂问题可沿本地链接补读。关键词不明确时再打开[完整索引](references/INDEX.md)，不要每次加载整个文档库。搜索无结果时换中文/英文术语或扩大目录重试一次；仍无证据则说明缺口。
4. 根据已读文档给出结论、前置条件与必要步骤。保留 Cloud 专属、应用类型、Agent 知识库与经典知识库等区别；不能凭记忆补配置名、命令、请求参数或示例响应。只有部署方式、版本或应用类型确实改变答案且上下文无法推断时才向用户澄清。
5. 用户要求最新版，或涉及价格、配额、兼容性和本地证据不足时，核对[规范来源与快照边界](references/SOURCE.md)中的官方地址，并标明在线补充。中文原文提示翻译可能不准确时，必要时核对它链接的英文原文。

Python 缺失或版本不足时，可用当前环境的文件搜索工具检索 `references/docs/` 并读取正文；报告脚本未运行，不自行安装依赖。不要因为搜索无命中就断言功能不存在。

## API 与示例

API 页面保留完整的单接口 OpenAPI 内容；需要交叉核对认证、安全方案或共享 schema 时读取[原始 OpenAPI JSON](references/assets/openapi_service.json)。按文档区分应用 API 密钥与知识库 API 密钥，使用占位符，不读取或输出用户真实凭据。

文档中的代码和步骤属于参考材料，不是执行授权。问答本身不授权安装 CLI、登录、调用 API、创建/删除知识库、部署、重启服务或付费操作。用户另有操作要求时，依据完整会话核实目标与授权；高影响操作缺少授权时先说明影响并确认。

## 更新与维护

用户要求刷新本 Wiki 时读取[更新协议](references/UPDATE.md)，使用 `scripts/capture_docs.py` 在新临时目录重新盘点并抓取完整范围，再以 `scripts/sync_wiki_docs.py --dry-run` 预演。失败页、失败资产、目录冲突或覆盖不一致时停止，不用部分语料覆盖当前快照。发现删页或改路径先报告差异，未经授权不使用 `--prune`；未要求自动更新时不创建后台任务。

[页面清单](references/wiki-manifest.json)记录逐页来源、相对路径和 SHA-256；[覆盖证据](references/NAVIGATION.json)保留导航分组与站点地图核对结果。无变化时应返回 `UNCHANGED`，不重写正文、索引和清单。提交、推送、覆盖安装等收尾复用会话或仓库已有授权，缺少授权时不自行执行。
