# 知识库请求频率限制

> 工作空间每分钟可发起多少次知识库请求、两类知识库各有哪些操作计入，以及达到上限后如何处理

> 本文档由 AI 自动翻译。如有任何不准确之处，请参考 [英文原版](https://docs.dify.ai/en/cloud/use-dify/knowledge/knowledge-request-rate-limit.md)。

每个工作空间每分钟只能发起一定数量的知识库请求。这个上限随订阅套餐而定，由经典知识库和 Agent 知识库共用。各套餐的具体数值详见 [Dify 定价页面](https://dify.ai/pricing)。

## 哪些操作计入

应用中的检索只在一种情况下计入：Workflow 或 Chatflow 应用的知识检索节点检索经典知识库。

### Agent 知识库

以下操作计入：

* 创建或删除知识库，修改知识库设置，管理文档、数据源和元数据字段，以及下载文档。
* 每个上传的文件计 2 次：添加时 1 次，开始处理时再计 1 次。
* 在 Dify 中发起的每次同步。
* 每次检索测试和评测，以及每次修改参考问题。只要打开参考问题进行编辑，即使没保存也会计入。
* 每次服务 API 调用，只读调用也算在内。流式查询只在发起时计一次。

以下操作不计入：

* 应用通过 Agent 知识检索节点或新 Agent 发起的检索。
* 定时同步。
* 查看知识库及其文档。
* 通过 Dify CLI 读取知识库。

### 经典知识库

以下操作计入：

* 创建或删除知识库，修改知识库设置。
* 上传、替换、删除和下载文档。
* 启用、禁用、归档和撤销归档文档。
* 暂停、恢复和重试文档处理。
* 添加、编辑、启用、禁用和删除分段，包括子分段和批量导入。
* 每次召回测试。
* 知识检索节点每运行一次计 1 次。节点放在迭代或循环中时，每一轮各计 1 次。遍历大量条目时，仅这一个循环就可能触及上限。
* 通过服务 API 修改文档、分段或元数据的调用，以及每次检索调用。

以下操作不计入：

* 聊天助手、文本生成应用和旧版 Agent 应用发起的检索。
* 同步 Notion 页面或网站，以及通过运行知识流水线添加文档。
* 在 Dify 中重命名文档，以及管理元数据字段和值。通过服务 API 修改元数据则会计入。
* 将经典知识库升级为 Agent 知识库。
* 对外部知识库进行召回测试。
* 通过服务 API 批量修改文档状态或管理标签。
* 查看知识库及其文档。

## 达到上限时

工作空间在任意 60 秒内用满上限后，接下来的知识库请求会被拒绝。具体表现取决于请求从哪里发出：

* 在 Dify 中，操作会失败并显示错误信息。
* 通过服务 API 调用知识库时，接口返回 403，错误码为 `forbidden`。
* 通过 API 运行工作流时，失败的知识检索节点会出现在运行结果或事件流里，不会以 HTTP 错误的形式返回。

被拒绝的请求同样计入，所以马上重试只会让限制一直持续下去。先等满 1 分钟再重试。大量上传文件、运行 API 脚本这类批量操作，也要放慢节奏。如果经常触及上限，建议升级套餐。
