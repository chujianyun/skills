# 从经典知识库升级到 Agent 知识库

> 将经典知识库迁移为 Agent 知识库

> 本文档由 AI 自动翻译。如有任何不准确之处，请参考 [英文原版](https://docs.dify.ai/en/cloud/use-dify/knowledge-base/upgrade-from-classic.md)。

升级会新建一个 [Agent 知识库](Agent%20%E7%9F%A5%E8%AF%86%E5%BA%93.md)，内容取自原有的 [经典知识库](../%E7%BB%8F%E5%85%B8%E7%9F%A5%E8%AF%86%E5%BA%93/%E7%BB%8F%E5%85%B8%E7%9F%A5%E8%AF%86%E5%BA%93.md)，经典知识库本身保持不变。在你切换之前，应用会继续用经典知识库作答，因此你可按自己的节奏检查和测试 Agent 知识库。

Agent 知识库可供 [Workflow 和 Chatflow 应用](../../%E7%BC%96%E6%8E%92/Workflow%20%E4%B8%8E%20Chatflow/Workflow%20%E4%B8%8E%20Chatflow.md)、[新 Agent](../../%E7%BC%96%E6%8E%92/Agent/Agent.md)、[服务 API](../../../%E5%BC%80%E5%8F%91%E8%80%85%E8%B5%84%E6%BA%90/API/%E6%8C%87%E5%8D%97/API%20%E6%A6%82%E8%A7%88/%E7%9F%A5%E8%AF%86%E5%BA%93/Agent%20%E7%9F%A5%E8%AF%86%E5%BA%93%20API.md) 和 [Dify CLI](%E6%8E%A5%E5%85%A5%E5%BA%94%E7%94%A8%E3%80%81Agent%20%E5%92%8C%E4%BB%A3%E7%A0%81.md#from-your-coding-agent) 使用。聊天助手、旧版 Agent 和文本生成应用则继续使用经典知识库。

两者有哪些不同，详见 [对比](../%E7%9F%A5%E8%AF%86%E5%BA%93.md#compare)。

## 哪些内容会迁移

升级会把内容迁入 Agent 知识库，并在那里重新索引每个文档。章节、摘要和分段都会重新生成，与经典知识库中的不会一一对应。

以下内容会一并迁移：

* **文档**：已上传的文件会重新上传；Notion 页面和抓取的网站则通过升级时自动创建的数据源导入。

* **元数据**：包括元数据字段和每个文档的字段值，因此可在 Agent 知识检索节点上设置相同的过滤条件。

* **检索设置**：Top K、分数阈值，以及嵌入模型和重排序模型。若其中某个模型未设置或已不可用，则改用工作空间的默认模型。

* **访问设置**：**可见权限** 设置会迁移；如果经典知识库开启了 **API 访问**，该设置也会一并迁移。只有当已发布的 Workflow 或 Chatflow 应用用过该经典知识库时，**工作流访问** 才会默认开启。

  为 **所有知识库** 创建的密钥同样能访问 Agent 知识库，限定了范围的密钥则不能。无论哪种情况，你的代码都需要调用 Agent 知识库的 [专属 API](../../../%E5%BC%80%E5%8F%91%E8%80%85%E8%B5%84%E6%BA%90/API/%E6%8C%87%E5%8D%97/API%20%E6%A6%82%E8%A7%88/%E7%9F%A5%E8%AF%86%E5%BA%93/Agent%20%E7%9F%A5%E8%AF%86%E5%BA%93%20API.md)，并传入它的新 ID。

* **基本信息**：名称、描述和标签。

推理模型和 [检索深度](%E6%A3%80%E7%B4%A2%E8%AE%BE%E7%BD%AE.md#retrieval-depth) 在经典知识库中没有对应的设置。推理模型初始为工作空间的默认模型，检索深度初始为「快速」。

之后如果更换推理模型，升级迁入的文档仍保留工作空间默认模型构建的内容，直到你重新索引为止。知识库较大时，升级前先确认工作空间的默认推理模型就是你想用的那个。

## 升级为 Agent 知识库

> [!NOTE]
>
> 开始之前，请确认：
>
> * 你拥有该经典知识库的编辑权限。
> * 工作空间已设置默认的系统推理模型、嵌入模型和重排序模型。
> * 该经典知识库不是外部知识库，也不是用知识流水线构建的知识库。这两类都无法升级，可改为 [创建 Agent 知识库](%E5%88%9B%E5%BB%BA%20Agent%20%E7%9F%A5%E8%AF%86%E5%BA%93.md)，再添加原有内容。
> * 每个已上传的文件都不超过 15 MB。只要有一个文件超出大小，或格式不受 Agent 知识库支持，整个升级就会失败。开始前，先在经典知识库中拆分或替换这类文件。
> * 如有 Notion 页面，已在 **集成** > **数据来源** 中连接同一个 Notion 工作空间。如有抓取的网站，当时使用的抓取服务提供商也已在此处连接。

升级会重新索引所有文档，并消耗推理模型和嵌入模型的 token。知识库较大时，先知会负责管控模型费用的同事。

在 **知识库** 中打开该经典知识库的菜单，开始升级。升级在后台进行，进度显示在 **Agent** 下。

视知识库大小，升级可能需要几分钟到几小时。

> [!NOTE]
>
> 升级创建的数据源默认仅手动同步。如果希望内容持续更新，需为每个数据源设置同步策略。

## 切换应用

切换之前，先 [检查已索引的文档](%E6%A3%80%E6%9F%A5%E5%B7%B2%E7%B4%A2%E5%BC%95%E7%9A%84%E6%96%87%E6%A1%A3.md)，并用应用实际会遇到的问题 [测试检索效果](%E6%B5%8B%E8%AF%95%E5%B9%B6%E8%B0%83%E4%BC%98%E6%A3%80%E7%B4%A2.md)。

如果 Agent 知识库的 **工作流访问** 处于关闭状态，先在它的 **设置** 中开启。然后在工作流中：

1. 添加一个 [Agent 知识检索节点](../../%E7%BC%96%E6%8E%92/Workflow%20%E4%B8%8E%20Chatflow/%E8%8A%82%E7%82%B9/Agent%20%E7%9F%A5%E8%AF%86%E6%A3%80%E7%B4%A2.md)，让它检索该 Agent 知识库，并接到原知识检索节点所在的位置。在节点上设置相同的元数据过滤条件，再把后续节点（例如 LLM 节点的 **上下文**）改为引用它的 `result`。

2. 运行测试。确认应用能基于 Agent 知识库给出满意的回答后，删除原知识检索节点，然后发布。

只有在所有应用都不再使用该经典知识库时，才可将其删除，其中也包括无法切换的聊天助手、旧版 Agent 和文本生成应用。
