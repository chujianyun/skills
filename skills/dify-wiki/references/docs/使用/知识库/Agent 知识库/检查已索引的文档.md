# 检查已索引的文档

> 查看文档是如何拆分、如何生成摘要的，并修正处理得不理想的内容

> 本文档由 AI 自动翻译。如有任何不准确之处，请参考 [英文原版](https://docs.dify.ai/en/cloud/use-dify/knowledge-base/review-indexed-documents.md)。

文档在 **文档** 页面显示为 **就绪** 后，打开它即可查看索引结果。

## 检查章节和摘要

**目录** 以源文档自带的标题为起点，推理模型还会按语义补充子章节，所以这里的目录可能和文档原本的目录不一样。

每个章节都附有摘要。以 [「研究」深度](%E6%A3%80%E7%B4%A2%E8%AE%BE%E7%BD%AE.md#retrieval-depth) 检索时，系统会根据这些摘要决定要阅读哪些章节。摘要没抓住重点，相关内容就更难找到。

**检查要点**：有没有章节把两个不相关的主题合在了一起，或者摘要没有概括出章节在讲什么。

**修正方法**：把源内容的标题写得更清楚，主题句写得更明确，让模型更容易判断章节从哪里开始、各自讲什么。

## 检查分段

每个章节内的文本会再切分为分段，也就是检索时搜索和返回的单位。每个分段应包含一个完整的主题。

行数较多的表格（例如价目表）会特意按行切分，每行一个分段。

每个分段最多 1,200 个字符，超出的内容（例如很长的代码块）会在上限处截断。

**检查要点**：有没有分段混杂了不相关的主题，或者把一段操作步骤、定义、列表或代码块从中间切开。

**修正方法**：调整源内容的结构，让每个标题只讲一个主题、每个段落只表达一个意思；需要一起检索到的内容放在同一个标题下，并控制在分段长度上限以内。

## 检查图片

如果推理模型和嵌入模型都只支持文本，图片只会保留图注或替代文本，检索也只能通过这些文字找到图片。

**检查要点**：用户可能会问到的图片，在源内容中是否缺少图注或替代文本。

**修正方法**：在源内容中为图片补上图注或替代文本；也可以换用支持视觉的嵌入模型，再在该文档上点击 **重新索引**，让图片可以按画面内容被检索到。详见 [多模态检索](%E5%A4%9A%E6%A8%A1%E6%80%81%E6%A3%80%E7%B4%A2.md)。

## 应用修改

修改源内容后，按以下方式导入新版本：

* 来自已连接数据源的文档，会在下次同步时更新。如需立即导入，在 **数据源** 页面点击 **立即同步**。

* 上传的文件，需删除旧文档，再上传新文件。

  > [!NOTE]
  >
  > 上传同名文件会新增一个文档，不会替换原有文档。

不同模型拆分内容和生成摘要的方式各不相同，因此也可以在 **设置** > **检索** 中换用其他推理模型。已索引的文档仍保留原模型构建的内容。要用新模型重建某个文档，在该文档上点击 **重新索引**。
