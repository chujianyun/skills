# 检索设置

> 控制知识库在检索时如何查找分段、如何为分段排序

> 本文档由 AI 自动翻译。如有任何不准确之处，请参考 [英文原版](https://docs.dify.ai/en/cloud/use-dify/knowledge-base/retrieval-settings.md)。

这些设置位于知识库的 **设置** > **检索** 中。

> [!TIP]
>
> 每次只调整一项设置，然后重新测试，这样才能判断每项改动是否有效。

| 设置项 | 作用 |
| :- | :- |
| **系统推理模型** | 索引时，按语义将文档拆分为分段和章节，为每个章节撰写摘要，并构建知识图谱，记录每个分段提到的主题以及这些主题之间的关联。  使用「深度」和「研究」检索时，负责规划检索步骤。  更换该模型不消耗 token：已索引的文档仍保留原模型构建的内容。要用新模型重建某个文档，在该文档上点击 **重新索引**。 |
| **Embedding 模型** | 将每个分段转换为向量，以便按语义将问题与分段匹配。  更换该模型会为所有文档重新生成向量，并消耗 token。 |
| **Rerank 模型** | 按相关性为检索到的分段排序，并为每个分段打分。 |
| **检索深度** | 每次检索的深入程度。详见下方的 [检索深度](%E6%A3%80%E7%B4%A2%E8%AE%BE%E7%BD%AE.md#retrieval-depth)。 |
| **Top K** | 每次检索最多返回的分段数。 值越大，上下文越多，干扰也越多；值越小，结果越集中，但可能漏掉相关分段。 |
| **Score 阈值** | 舍弃得分低于设定阈值的分段。 阈值越高，只留下高度匹配的分段，但可能什么都返回不了；阈值越低，匹配度一般的分段也能通过。 |

## 检索深度

三种深度都会用到嵌入模型和重排序模型，「深度」和「研究」还会用到推理模型。

| 深度 | 作用 |
| :- | :- |
| **快速** | 按语义和关键词将问题与分段匹配。速度最快，足以应对大多数直接的问题，建议从这里开始。 |
| **深度** | 检索范围比「快速」更广，还会沿着知识图谱，从问题出发找到涉及相关主题的分段。速度较慢。  答案分散在多个相关主题中、「快速」又总是漏掉时，就改用它。 |
| **研究** | 将复杂问题拆解为多个子问题，逐一广泛检索，并根据章节标题和摘要决定阅读哪些章节。  速度最慢，消耗的模型 token 也最多。适合需要多次检索才能回答的问题，不适合直接的问题。 |
