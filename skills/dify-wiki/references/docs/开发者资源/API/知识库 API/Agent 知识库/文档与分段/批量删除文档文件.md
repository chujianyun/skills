# 批量删除文档文件

> 一次调用请求删除最多 100 个文档文件，并返回每个文件的处理结果。与 [删除文档文件](%E5%88%A0%E9%99%A4%E6%96%87%E6%A1%A3%E6%96%87%E4%BB%B6.md) 一样，不要删除生效修订版本的文件。

此 `DELETE` 请求需携带 JSON 请求体。如果客户端默认不为 DELETE 请求发送请求体，需将其配置为显式发送。

文件先按 `documentId`、再按 `expectedRevision` 排序，并逐个独立处理。文件不存在、`expectedRevision` 已过时、已在删除中，或该密钥无权删除时，该文件会以 `rejected` 出现在 `results` 中，其他文件照常处理。遇到基础设施故障时，处理会中止，剩余文件保持 `pending`。

基础设施故障后，或整个调用失败后，如需继续，使用同一个 `Idempotency-Key` 再次发送相同的请求。它会返回原批次及其中已受理的作业，并且只重试 `pending` 的文件。

此调用不会创建批量任务。

删除流程详见 [删除文档和数据源](../../../%E6%8C%87%E5%8D%97/API%20%E6%A6%82%E8%A7%88/%E7%9F%A5%E8%AF%86%E5%BA%93/Agent%20%E7%9F%A5%E8%AF%86%E5%BA%93%20API.md#delete-documents-and-sources)。
