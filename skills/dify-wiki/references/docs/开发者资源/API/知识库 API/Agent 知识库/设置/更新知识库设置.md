# 更新知识库设置

> 更改知识库的嵌入模型或检索设置。在内容索引前后如何设置模型，详见 [更换模型或检索设置](../../../%E6%8C%87%E5%8D%97/API%20%E6%A6%82%E8%A7%88/%E7%9F%A5%E8%AF%86%E5%BA%93/Agent%20%E7%9F%A5%E8%AF%86%E5%BA%93%20API.md#change-models-or-retrieval-settings)。

具体行为取决于模型是否已经生效：

- 第一个文档完成索引前，设置会保存为待生效状态，调用返回 `200`。这些设置会在第一个文档索引时校验并生效。省略 `embedding` 或 `retrieval` 时，该组设置保持其待生效的值。
- 模型生效后，调用返回 `202`，更改以迁移的方式进行。用 `migration.id` 轮询 [获取设置迁移](%E8%8E%B7%E5%8F%96%E8%AE%BE%E7%BD%AE%E8%BF%81%E7%A7%BB.md)，直到迁移结束，再读取最终设置。无需迁移的更改（例如重新发送当前生效的嵌入模型）返回 `200`。

更换嵌入模型会重新嵌入所有文档。检索设置的更改，包括更换推理模型，都无需重建即可生效：已索引的文档仍保留原模型构建的内容，直到你用 [重新索引文档](../%E6%96%87%E6%A1%A3%E4%B8%8E%E5%88%86%E6%AE%B5/%E9%87%8D%E6%96%B0%E7%B4%A2%E5%BC%95%E6%96%87%E6%A1%A3.md) 重新索引为止。

规则：

- 至少发送 `embedding` 或 `retrieval` 之一。模型生效后，每次调用只能发送其中一个。
- `retrieval` 需要已启用的重排序模型：同时发送 `rerank.enabled: true` 和 `rerank.model`。
- `retrieval` 需要嵌入模型，可在同一次调用中发送，也可以是之前已保存的。否则调用返回 `409`。
- `scoreThreshold.enabled: true` 时必须提供 `scoreThreshold.value`。
