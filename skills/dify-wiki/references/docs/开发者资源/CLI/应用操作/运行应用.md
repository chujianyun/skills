# 运行应用

> 用 difyctl 运行 Dify 应用，传入变量和文件，流式查看或停止耗时较长的运行，填写人工介入表单，并排查运行失败的原因

> 本文档由 AI 自动翻译。如有任何不准确之处，请参考 [英文原版](https://docs.dify.ai/en/cli/run-apps.md)。

> [!TIP]
>
> 要交给编码 Agent 来做，先 [为它配置好 `difyctl` Skill](https://docs.dify.ai/zh/cli/get-started#配置编码-agent)，再把这个页面发给它。

## 查找应用

运行 `difyctl get console_app` 列出你的应用。只有开启了服务 API 访问的应用才会列出，也只有这些应用能运行。

```bash theme={null}
difyctl get console_app

# 按名称片段或 mode 筛选，也可两者同时使用
difyctl get console_app --name report --mode workflow
```

在其他命令中，把应用的 `id` 传给 `--app-id`。`mode` 是应用的类型，决定了用哪条命令运行它：

| `mode` | 应用类型 | 运行命令 |
| :- | :- | :- |
| `workflow` | Workflow | `run console_app workflow` |
| `advanced-chat` | Chatflow | `run console_app advanced_chat` |
| `chat` | 聊天助手 | `run console_app chat` |
| `agent-chat` | 旧版 Agent | `run console_app chat` |
| `completion` | 文本生成应用 | `run console_app completion` |

> [!NOTE]
>
> `difyctl` 不会列出或运行用新 Agent 构建的应用。这类应用要改为通过 [服务 API](../../API/%E6%8C%87%E5%8D%97/API%20%E6%A6%82%E8%A7%88/Agent%20API.md) 调用。

## 查看应用的输入变量

运行 `difyctl describe console_app` 查看应用的变量：名称、类型，以及哪些是必填的。

```bash theme={null}
difyctl describe console_app --app-id 7f3e9a2b-1c4d-4e8f-9a0b-2d5c8e1f4a7b
```

## 运行 Workflow 应用

用 `--inputs` 把应用的变量传给 `difyctl run console_app workflow`，格式为以变量名为键的 JSON。应用的答案在结果的 `outputs` 中，键名对应输出节点的变量。

```bash theme={null}
difyctl run console_app workflow --app-id 7f3e9a2b-1c4d-4e8f-9a0b-2d5c8e1f4a7b --inputs '{"topic": "季度报告"}'

# 从文件读取变量
difyctl run console_app workflow --app-id 7f3e9a2b-1c4d-4e8f-9a0b-2d5c8e1f4a7b --inputs @inputs.json
```

> [!NOTE]
>
> 必填变量名拼错时，运行会失败，报 `topic is required in input form` 之类的错误。可选变量名拼错则不会报错，运行会直接略过这个变量。变量名可用 [`describe console_app`](#查看应用的输入变量) 核对。

## 发送消息或生成文本

按 [查找应用](%E8%BF%90%E8%A1%8C%E5%BA%94%E7%94%A8.md#查找应用) 中的应用类型，选用对应的 `run console_app` 命令。消息放在 `--query` 中，变量（如有）放在 `--inputs` 中。文本生成应用通常只需要 `--inputs`。回复在结果的 `text.answer` 中。

```bash theme={null}
# 聊天助手或旧版 Agent 应用
difyctl run console_app chat --app-id 0a1b2c3d-4e5f-6789-abcd-ef0123456789 --query "你们的营业时间是几点？"

# 带一个变量的 Chatflow 应用
difyctl run console_app advanced_chat --app-id 3c4d5e6f-7a8b-4c9d-8e0f-1a2b3c4d5e6f --query "这个季度有什么变化？" --inputs '{"topic": "季度报告"}'

# 文本生成应用
difyctl run console_app completion --app-id 5e6f7a8b-9c0d-4e1f-a2b3-c4d5e6f7a8b9 --inputs '{"topic": "季度报告"}'
```

## 继续会话

用 `--conversation-id` 传回结果中的 `conversation_id`。

```bash theme={null}
difyctl run console_app advanced_chat --app-id 3c4d5e6f-7a8b-4c9d-8e0f-1a2b3c4d5e6f --query "这个季度有什么变化？" --inputs '{"topic": "季度报告"}'

# 在同一会话中回复，变量保持不变
difyctl run console_app advanced_chat --app-id 3c4d5e6f-7a8b-4c9d-8e0f-1a2b3c4d5e6f --conversation-id 9f8e7d6c-5b4a-4321-8fed-cba987654321 --query "那上个季度呢？" --inputs '{"topic": "季度报告"}'
```

> [!NOTE]
>
> 每轮对话都要重新传入应用的必填变量。漏传时，消息会发送失败。

Chatflow 应用的运行被停止，或在表单处暂停时，返回的结果中没有 `conversation_id`。运行被停止后，会话仍可接收新消息。要在这些情况下拿到这个 ID，启动运行时就加上 `--stream`：每个事件的顶层都带有 `conversation_id`。

## 发送文件

任何运行命令都可用 `--files` 为每个文件变量指定一个本地路径。文件列表变量则指定一组路径。网络上的文件改为通过 `--inputs` 传入。每个文件变量只能通过 `--files` 或 `--inputs` 中的一个传入，不能两处都传。

```bash theme={null}
difyctl run console_app workflow --app-id 7f3e9a2b-1c4d-4e8f-9a0b-2d5c8e1f4a7b --inputs '{"topic": "季度报告"}' --files '{"document": "./report.pdf", "appendices": ["./q1.pdf", "./q2.pdf"]}'

# 网络上的文件
difyctl run console_app workflow --app-id 7f3e9a2b-1c4d-4e8f-9a0b-2d5c8e1f4a7b --inputs '{"document": {"transfer_method": "remote_url", "url": "https://example.com/report.pdf", "type": "document"}}'
```

## 跟踪耗时较长的运行

要边运行边查看进展，就加上 `--stream`。每个事件一发生就会打印出来，每行一个 JSON 对象。Workflow 应用运行时，最后一个事件 `workflow_finished` 会在 `data.outputs` 中给出结果。只想打印部分事件时，用 `--only` 逐个指定事件名。

```bash theme={null}
difyctl run console_app workflow --app-id 7f3e9a2b-1c4d-4e8f-9a0b-2d5c8e1f4a7b --inputs '{"topic": "季度报告"}' --stream

# 只打印最后一个事件
difyctl run console_app workflow --app-id 7f3e9a2b-1c4d-4e8f-9a0b-2d5c8e1f4a7b --inputs '{"topic": "季度报告"}' --stream --only workflow_finished
```

## 停止运行

要停止 Workflow 或 Chatflow 应用的运行，无论它仍在进行，还是在人工介入表单处暂停，都把它的运行 ID 传给 `difyctl stop run`。运行 ID 是 `suspended` 或 `incomplete` 结果中的 `run_id`。用了 `--stream` 时，从 `workflow_started` 事件中取 `workflow_run_id`。

聊天助手、旧版 Agent 应用或文本生成应用的回复，改用 [`stop task`](#停止聊天助手、旧版-agent-应用或文本生成应用的回复) 停止。

```bash theme={null}
difyctl stop run --app-id 7f3e9a2b-1c4d-4e8f-9a0b-2d5c8e1f4a7b --run-id 4b5c6d7e-8f90-4a1b-b2c3-d4e5f6a7b8c9

# 没有运行 ID 时，例如运行是从 Web 应用启动的：列出正在进行的运行
difyctl get run --app-id 7f3e9a2b-1c4d-4e8f-9a0b-2d5c8e1f4a7b --triggered-from app-run --status running

# 在表单处暂停的运行：去掉 --status，找 status 为 paused 的运行
difyctl get run --app-id 7f3e9a2b-1c4d-4e8f-9a0b-2d5c8e1f4a7b --triggered-from app-run

# 确认 status 为 stopped；停止后可能会先短暂显示 running
difyctl describe run --app-id 7f3e9a2b-1c4d-4e8f-9a0b-2d5c8e1f4a7b --run-id 4b5c6d7e-8f90-4a1b-b2c3-d4e5f6a7b8c9
```

> [!NOTE]
>
> 在 Workflow 或 Chatflow 应用运行期间按下 Ctrl+C，只会停止 `difyctl`，服务器上的运行不会停止。要连运行一起停止，把它的运行 ID 传给 `stop run`。

停止运行时已经发出的模型调用或 HTTP 请求，仍会执行完。

在脚本中，停止看起来和失败一样。要区分两者，详见 [判断运行如何结束](../%E5%8F%82%E8%80%83/%E7%BB%93%E6%9E%9C%E3%80%81%E9%94%99%E8%AF%AF%E4%B8%8E%E9%80%80%E5%87%BA%E7%A0%81.md#判断运行如何结束)。

## 停止聊天助手、旧版 Agent 应用或文本生成应用的回复

要想能停止回复，就得用 `--stream` 启动它。然后把它第一个事件中的 `task_id` 传给 `difyctl stop task`。

```bash theme={null}
difyctl stop task --app-id 0a1b2c3d-4e5f-6789-abcd-ef0123456789 --task-id 26992456-d005-4add-a26d-8dff91d5f13d
```

> [!NOTE]
>
> 即使任务 ID 不存在，或回复已经结束，`stop task` 也会打印 `{"result": "success"}`。所以要确认 `task_id` 来自你要停止的那条回复，并趁它的流还没结束时运行 `stop task`。
>
> 被停止的回复看起来和正常结束的回复一样：流以 `message_end` 结束，启动回复的命令以退出码 0 退出。回答中只有停止前已收到的内容。如果脚本要用到回答，就让它记下自己调用过 `stop task`。

## 填写人工介入表单

> [!NOTE]
>
> 只有人工介入节点的提交方式为 **Webapp** 时，才能在 `difyctl` 中填写表单。

运行在表单处暂停时，会返回 `status` 为 `suspended` 的结果，每个操作按钮各对应一条提示。找到你要执行的操作对应的提示，把其中 `inputs` 里的每个 `null` 换成你的回答，再 [运行这条提示](../%E6%9F%A5%E6%89%BE%E5%B9%B6%E8%BF%90%E8%A1%8C%E5%91%BD%E4%BB%A4.md#按提示运行后续命令)。

也可先看看表单有哪些字段再填写：从任一提示中取出 `form_token`，用 `describe run form` 查看，再用 `submit run form` 提交回答。

无论用哪种方式，之后都用 `get run event` 跟踪恢复后的运行，把暂停时返回结果中的 `run_id` 传给 `--run-id`。一定要带上 `--include-state-snapshot`，否则该命令可能长达 5 分钟没有任何输出。

```bash theme={null}
# 查看表单字段
difyctl describe run form --app-id 7f3e9a2b-1c4d-4e8f-9a0b-2d5c8e1f4a7b --form-token Xq7Lm2RtPz9KcV4bN8wJdE

# 选择一个操作并提交；表单没有字段时，用 --inputs '{}'
difyctl submit run form --app-id 7f3e9a2b-1c4d-4e8f-9a0b-2d5c8e1f4a7b --form-token Xq7Lm2RtPz9KcV4bN8wJdE --action approve --inputs '{"comment": "没问题"}'

# 跟踪恢复后的运行
difyctl get run event --app-id 7f3e9a2b-1c4d-4e8f-9a0b-2d5c8e1f4a7b --run-id 4b5c6d7e-8f90-4a1b-b2c3-d4e5f6a7b8c9 --include-state-snapshot

# 如果运行之后还可能在其他表单处暂停，持续跟踪
difyctl get run event --app-id 7f3e9a2b-1c4d-4e8f-9a0b-2d5c8e1f4a7b --run-id 4b5c6d7e-8f90-4a1b-b2c3-d4e5f6a7b8c9 --include-state-snapshot --continue-on-pause
```

## 排查运行失败的原因

Workflow 或 Chatflow 应用运行失败时，可从失败结果中的 `run_id` 入手，也可用 `difyctl get run` 列出失败的运行。然后用 `describe run` 查看这次运行，用 `get run node` 查看它的各个节点。

```bash theme={null}
difyctl get run --app-id 7f3e9a2b-1c4d-4e8f-9a0b-2d5c8e1f4a7b --triggered-from app-run --status failed

# 运行的输入、输出、状态和错误
difyctl describe run --app-id 7f3e9a2b-1c4d-4e8f-9a0b-2d5c8e1f4a7b --run-id 4b5c6d7e-8f90-4a1b-b2c3-d4e5f6a7b8c9

# 各个节点；失败的节点带有错误信息
difyctl get run node --app-id 7f3e9a2b-1c4d-4e8f-9a0b-2d5c8e1f4a7b --run-id 4b5c6d7e-8f90-4a1b-b2c3-d4e5f6a7b8c9
```

> [!NOTE]
>
> 一定要带上 `--triggered-from app-run`。不带的话，列表只显示草稿的测试运行。

## 故障排查

| 错误信息 | 处理方法 |
| :- | :- |
| `invalid run input`，但输入无误 | 应用可能从未发布过。发布后再运行。 |
| `stop run` 或 `get run event` 报 `unknown flag "--task-id"` | 改用 `--run-id` 传入运行 ID，例如结果中的 `run_id`。要按 `task_id` 停止聊天助手、旧版 Agent 应用或文本生成应用的回复，用 [`stop task`](#停止聊天助手、旧版-agent-应用或文本生成应用的回复)。 |
| `run_not_found` | 检查传入的是运行 ID 而不是 `task_id`，并确认 `--app-id` 是该运行所属的应用。 |
| `run_not_stoppable` | 先用 `describe run` 查看运行状态。如果运行已经结束，就无需停止。 如果运行仍在进行，或在表单处暂停，说明它是在服务器升级之前启动的。如果它停在表单处，而且是你的账号启动的（用 `difyctl` 启动，或作为测试运行启动），先用它的运行 ID 和 `--include-state-snapshot` 运行一次 `get run event`，再重新运行 `stop run`。其他此类运行无法用 `difyctl` 停止。 |
| `stop run` 或 `stop task` 报 `app_mode_mismatch` | Workflow 或 Chatflow 应用的运行用 `stop run` 停止，其他应用的回复用 [`stop task`](#停止聊天助手、旧版-agent-应用或文本生成应用的回复) 停止。 |

任何命令都可能遇到的错误，详见「结果、错误与退出码」中的 [故障排查](../%E5%8F%82%E8%80%83/%E7%BB%93%E6%9E%9C%E3%80%81%E9%94%99%E8%AF%AF%E4%B8%8E%E9%80%80%E5%87%BA%E7%A0%81.md#故障排查)。
