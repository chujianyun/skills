# 构建应用

> 让编码 Agent 构建、修改、测试并发布你的 Workflow 和 Chatflow 应用

> 本文档由 AI 自动翻译。如有任何不准确之处，请参考 [英文原版](https://docs.dify.ai/en/cli/build-apps.md)。

建议让编码 Agent 来构建应用。你只需描述应用、回答它的提问，并完成它做不了的设置。

## 开始之前

* Agent 已 [配置好](../%E5%BF%AB%E9%80%9F%E5%BC%80%E5%A7%8B.md#配置编码-agent)：装有 `difyctl` Skill，并已登录你的 Dify 服务器。
* Agent 登录所用的账户，角色为编辑或更高。
* 应用要用的模型已在 Dify 中配好 API 密钥。
* Agent 所在的机器上已安装 `jq`。
* 如果要修改现有应用，该应用已开启服务 API 访问。

## Agent 能做什么

描述你想要的新应用，或者指明一个现有应用，说清要改什么。Agent 会和你一起理清应用该做什么、怎么测试，再动手构建和测试。`difyctl` Skill 要求它只在你同意后才发布应用。

例如：

```text wrap theme={null}
构建一个 Chatflow 应用，根据我们帮助中心的知识库回答客户提问。
```

```text wrap theme={null}
构建一个 Workflow 应用，读取客服工单，按紧急程度分级，再起草一份回复。
```

你还可以让它：

* **验证应用**：测试单个节点或整个草稿，运行已发布的应用试试效果，或者排查失败的运行，看是哪个节点出了错、原因是什么。

* **发布**：查看应用能否发布、与上次发布的版本相比改了什么，然后发布。

* **回滚**：恢复到之前的某个发布版本，再重新发布。

  > [!WARNING]
  >
  > 恢复会覆盖草稿中所有未发布的更改。如果草稿里有你想保留的内容，先让 Agent 把草稿导出。

* **备好应用所需**：从 Marketplace 安装集成（需工作空间允许），并设置应用的环境变量。

* **管理应用**：导出应用的 DSL，开启或关闭它的 Web 应用，修改基本信息（名称、图标或描述）。如果 Agent 登录的账户是管理员或所有者，它还能开启或关闭应用的服务 API 访问。

## Agent 不能做什么

Agent 只能构建和修改 Workflow 与 Chatflow 应用。它能构建以触发器开头的工作流，但无法测试或运行它。

应用用到以下几项时，需要你亲自在 Dify 中完成：

* 为通过 OAuth 登录的工具授权。
* 从 GitHub 或包文件安装集成。
* 创建知识库并上传文档。

## Agent 工作期间

在 Agent 完成之前，不要在工作室中编辑这个应用，也别让团队成员改动它。只要有人在那里保存了更改，Agent 的下一次更新就会受阻。

Agent 为每个应用单独建一个文件夹来存放工作，这些文件夹都在 `difyctl/` 下，而 `difyctl/` 位于你启动 Agent 时所在的目录。保留这个文件夹，下次也从同一位置启动 Agent。这样它就能接着完成未完成的构建；你要求修改时，它也能在之前工作的基础上继续。
