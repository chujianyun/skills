# 发布插件

> 分发 Dify 插件的三种方式（Marketplace、GitHub 仓库或本地文件）以及如何选择合适的方式

> 本文档由 AI 自动翻译。如有任何不准确之处，请参考 [英文原版](https://docs.dify.ai/en/develop-plugin/publishing/marketplace-listing/release-overview.md)。

Dify 支持三种分发插件的方式。它们的区别在于事先经过多少审核，以及插件触达的受众范围有多广。

发布前，先完成开发和测试，并阅读 [插件开发指南](%E6%A0%87%E5%87%86/%E6%8F%92%E4%BB%B6%E5%BC%80%E5%8F%91%E6%8C%87%E5%8D%97.md)。

## 选择一种方式

> [card] [Marketplace](%E5%8F%91%E5%B8%83%E6%8F%92%E4%BB%B6%E5%88%B0%20Marketplace.md)
>
> 官方目录。经过审核、值得信赖，每位 Dify 用户都可一键安装。

> [card] [GitHub 仓库](GitHub%20%E4%BB%93%E5%BA%93/%E5%8F%91%E5%B8%83%E5%88%B0%E4%B8%AA%E4%BA%BA%20GitHub%20%E4%BB%93%E5%BA%93.md)
>
> 在 GitHub 上自托管。无需审核，用户通过仓库 URL 安装。

> [card] [本地文件](%E6%9C%AC%E5%9C%B0%E6%96%87%E4%BB%B6/%E6%89%93%E5%8C%85%E4%B8%BA%E6%9C%AC%E5%9C%B0%E6%96%87%E4%BB%B6%E5%B9%B6%E5%88%86%E4%BA%AB.md)
>
> 一个直接交付的 `.difypkg` 文件。适合私有或内部插件。

## 对比

| |  Marketplace |  GitHub |  本地文件 |
| :- | :- | :- | :- |
| **受众** | 每位 Dify 用户 | 任何拥有仓库 URL 的人 | 你交付文件的对象 |
| **审核** | 自动风险与软件包检查 + 人工审核 | 无 | 无 |
| **安装路径** | 在 Marketplace 界面一键安装 | 通过 GitHub 对话框安装 | 在插件页面上传 |
| **版本管理** | 每个版本都提交新软件包和新 PR | 带 `.difypkg` 资产的 GitHub 发布 | 重新打包并重新分发 |
| **适用场景** | 成熟且广泛适用的插件 | 开源项目、通过 URL 共享的内部工具 | 私有插件、内部测试、临时分发 |

> [!TIP]
>
> 许多开发者会 **先发布到 GitHub** 以快速迭代，待插件稳定后再提交到 **Marketplace**。同一个 `.difypkg` 文件适用于全部三种方式，区别只在于分发渠道。

## 经验法则

* **想要广泛触达并经过审核？** 使用 **Marketplace**。
* **想要完全掌控发布和版本管理？** 使用 **GitHub**。
* **私有或一次性使用？** 使用 **本地文件**。
