# 将流程挖掘操作化

机械流程可以通过在[Workshop](https://www.palantir.com/docs/foundry/workshop/overview/)中使用专用微件集成到操作应用程序中。虽然机械应用程序展示流程*定义*，但机械微件显示流程对象的\_实际\_状态。

微件的两个主要用途是：

* 为用户特定的工作流程创建流程的独特视图。定制显示的指标以及图形的外观。
* 通过深入研究流程对象的子集并可视化丰富的指标和节点着色来分析流程并识别瓶颈。

机械提供了**机械快速应用程序**，您可以使用它来启动应用程序开发，或作为现成的分析工具。要创建模块，请导航到机械应用程序的**概览**侧面板中的**模块**菜单并选择**创建模块**。

:::callout{theme="neutral"}
由机械管理的流程日志对象异步响应流程对象的更改。因此，注册事件可能会有轻微的延迟，聚合指标（不包括状态计数）可能不包括最新的事件。如果需要实时性能，请考虑使用手动设置或联系Palantir支持团队寻求帮助。
:::

## 机械流程概览微件

在Workshop中，您可以创建一个**机械流程概览**微件。选择包含您想要可视化流程的机械资源。Ontology配置以及节点位置将从该流程中发现。

### 输入数据

机械流程概览微件显示一组特定的流程对象。您可以通过Workshop对象集变量提供这些对象。为了确保一致性，您应该通过流程周围的搜索获得流程日志的变量。

默认情况下，*最后更新于*指的是每个流程对象的最新日志条目的时间戳。如果您选择自己维护流程对象类型上的**更新于**属性，可以在此覆盖该行为。

### 节点指标

机械流程概览微件根据最新状态及其进入该状态的时间计算一组默认指标。为了了解您的流程对象的行为，您可以从其他属性添加上下文。您可以在**自定义指标**部分基于流程和日志对象类型的所有属性定义数值指标。

### 节点和边样式

在这些部分中，您可以定义应用程序用户将如何查看流程。

### 图形输出

您可以使用机械流程概览微件控制Workshop应用程序的其他部分。图形上的用户交互可以控制对象集筛选或包含所选元素ID的字符串类型变量。

### 实时挖掘

通常，您应该首先建立一个抽象流程定义，然后将观察到的数据与其匹配。然而，如果您的主要目标是了解日志数据和流程实体的旅程，可能在机械中定义流程还为时过早。对于这种情况，机械提供了实时挖掘功能，即能够从操作数据中实时抽象出流程定义。

您可以选择将机械图表留空并创建一个带有机械微件的Workshop模块。我们建议利用“创建模块”功能。

在Workshop模块的编辑模式下访问机械微件的配置期间，您可以切换**启用实时挖掘**。当启用实时挖掘时，机械将识别您提供的日志对象集变量中存在的所有状态和过渡，并布置生成的节点。您可以筛选此对象集以探索数据子集，并实时观察这些对象形成的流程。

:::callout{theme="warning"}
实时挖掘的流程定义不会永久保存。您可以在画布上调整节点位置，但当日志对象集发生变化时，这些位置将被重置。由于实时挖掘的临时性质，在实时挖掘模式下不允许设置自动化。
:::
