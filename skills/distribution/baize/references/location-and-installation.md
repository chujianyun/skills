# 位置选择与安装

## 选择生成位置

按以下顺序判断，只采用第一条命中的规则：

1. 用户给出目标路径：使用该路径。
2. 当前选中的是受治理的 Skills 仓库：读取仓库 `AGENTS.md` 或同类规则。Wiki 型产物通常归入知识库类别，但必须采用仓库已有分类；把目标父目录设为该分类目录，并同步维护仓库要求的 taxonomy、README、marketplace 等注册文件。
3. 当前选中的是普通项目或工作目录：在当前目录创建 `<product-wiki>/`。
4. 没有项目/工作目录上下文，当前路径只是 home、临时目录或 Agent 默认运行目录：直接在当前 Agent 的 Skills 根目录创建。

不要把白泽自身安装目录误判为用户选择的输出目录。更新已有 Skill 时以其现有位置为准，不重新执行位置推断。

## 找到当前 Agent Skills 根目录

优先使用运行环境明确提供的 Skills 路径。没有显式路径时，`scripts/install_skill.py` 按以下顺序选择：

1. `BAIZE_AGENT_SKILLS_DIR`
2. `$CODEX_HOME/skills`
3. 已存在的 `~/.agents/skills`
4. `~/.codex/skills`

这些是运行时探测规则，不能把某台机器的绝对路径写进生成 Skill。

## 安装规则

- 生成目录已经位于当前 Agent Skills 根目录时，报告 `ALREADY_INSTALLED`，不复制。
- 目标不存在时可直接安装，这是用户“创建并自动安装”请求内的正常步骤。
- 已安装内容与源目录树哈希相同，报告 `UNCHANGED`，不改 mtime。
- 同名目标内容不同，先确认它是同一 Wiki 的旧版本；普通安装不得直接覆盖。
- 使用 `--replace` 时，安装脚本先把旧目录移动到 Agent Skills 根目录下的 `.baize-backups/`，再原子替换，便于恢复。
- 只安装到当前 Agent。是否给其他 Agent 建软链接、复制或发布，遵循当前项目规则或用户的明确要求。

## 仓库治理与发布边界

若在 Skills 仓库中创建：

1. 先保持生成 Skill 自身完整，再修改仓库级注册文件。
2. 使用仓库提供的校验脚本；注册、README、marketplace 和路径必须一致。
3. 只暂存本次 Skill 和它必需的注册变更，不捎带用户的其他修改。
4. 本地创建和安装不等于授权公开发布。提交、推送、市场发布是否授权，以仓库规则和用户要求为准。
5. 上游 Wiki 许可证不允许再分发或许可证不清楚时，不要加入公开仓库；改在本地 Agent Skills 目录生成，并在 `SOURCE.md` 标明限制。
