# 手动与自动更新

## 手动更新

1. 读取现有 `references/wiki-manifest.json`，锁定来源根、语言、版本和本地路径映射。
2. 按抓取协议重新盘点完整导航，抓到全新的临时目录；不要在现有文档上局部修改。
3. 运行 `sync_wiki_docs.py --dry-run`。
4. 覆盖率完整且没有未授权删页时正式同步。
5. 只有发生变化才重新验证和安装；`UNCHANGED` 时不触碰任何 Skill 文件。

## 自动更新授权

只有用户明确提出“自动更新、定期同步、每天/每周刷新”时才创建调度任务。用户的请求已经授权创建调度，但仍需明确以下缺失参数：

- 频率、时间和时区
- 目标 Skill 的绝对路径
- 上游删页或改路径时，是否持续授权使用 `--prune` 将旧文件移入可恢复归档
- 更新后是否需要执行仓库提交、推送或其他外部发布；这些不因“自动更新”自动获得授权

没有删页授权时，自动任务遇到 stale 页面应停止并通知用户，不要猜测上游删除是否有效。

## 调度任务内容

优先使用当前 Agent 提供的自动化/调度能力。任务提示应是可读的完整指令，至少包含：

```text
使用 $baize 更新 <absolute skill path>。从清单中的 source_root 重新盘点并抓取完整 Wiki 到临时目录，先运行同步 dry-run；只有覆盖率完整且通过安全边界时才应用。内容与元数据无变化时报告 UNCHANGED，不写入正文、索引或清单。未经持续授权不要 prune、提交、推送或发布。
```

若调度器需要项目 ID，先从当前 Agent 的项目列表选择与目标路径对应的项目，不编造。没有可用调度能力时，交付手动更新命令并说明限制；不要私自改系统 cron 或创建常驻进程。

## 无变化和失败语义

- `UNCHANGED`：成功检查，零文件写入；调度记录可以记录本次运行，Skill 本体不能只为时间戳而变化。
- `CHANGED`：只写变化页面、必要索引和清单，然后验证与安装。
- `INCOMPLETE`：页面失败或覆盖率不一致；零文件写入，保留旧快照。
- `STALE_REQUIRES_APPROVAL`：发现删页/改路径但无 prune 授权；零文件写入。
- `FAILED`：网络、鉴权、解析、校验或安装失败；报告具体阶段，不把旧 Skill 说成已更新。
