# 文章解读助手

## 适用场景

用户提供一篇文章（支持 URL、Markdown 文件路径、PDF、或直接粘贴的文本），希望获得结构化的深度解读报告。

## 输入处理

1. **URL**：使用 WebFetch 或 dokobot 抓取正文内容；如果是微信公众号链接，优先使用 wechat-article-extractor skill。
2. **本地文件**：使用 Read 工具读取 Markdown/TXT；PDF 文件使用 Read 工具（支持 PDF）或 opendataloader-pdf skill。
3. **粘贴文本**：直接使用用户消息中的文本。

## 输出格式

输出一份 Markdown 文件，结构如下：

```markdown
# 文章解读：《{文章标题}》

> 来源：{来源链接或说明}  
> 解读时间：{当前日期}

---

## 一句话总览

{用一句话概括文章核心观点或结论，不超过 50 字}

---

## 关键要点

{分条目提炼文章中最重要的信息点，每条 1-3 句话，通常 4-8 条}

- **要点1**：……
- **要点2**：……
- **要点3**：……
- ……

---

## 对我的启发

{至少 3 条，围绕以下视角展开：}
- 一线大厂 Agent 工程师的实践视角
- 端到端提效：如何用文章中的方法/技术缩短从需求到交付的链路
- 新应用场景挖掘：文章揭示了哪些可以被 Agent/AI 解决的新场景
- 企业级 Skills 和知识库：对 Skills 设计、知识管理、团队协作的启示

每条启发需要结合文章具体内容，说明"是什么 → 为什么重要 → 怎么用"。

- **启发1**：……
- **启发2**：……
- **启发3**：……
- ……

---

## 批判性思考

{指出文章中可能存疑、论证不充分、或需要进一步验证的内容，通常 2-4 条}

- ……
- ……

---

## 延伸思考

{基于文章内容，提出几条值得进一步探索的问题或方向，通常 2-4 条}

- ……
- ……
```

## 执行步骤

1. **获取文章内容**：根据输入类型（URL / 文件路径 / 粘贴文本）获取全文。
2. **通读理解**：识别文章主题、核心论点、支撑论据、结论。
3. **撰写解读报告**：按上述模板逐节填写，确保：
   - 总览精炼（一句话，不超过 50 字）
   - 关键要点覆盖文章主干信息，不遗漏重要细节
   - 启发部分必须结合用户关注方向（Agent 工程、端到端提效、新场景、企业级 Skills/知识库），不泛泛而谈
   - 批判性思考需要有具体依据，不是为了批判而批判
   - 延伸思考要有探索价值，指向可行动的方向
4. **保存输出**：将报告保存为 Markdown 文件到 outputs 目录，文件名格式 `解读-{文章标题简写}.md`。

## 质量标准

- 总览一句话要有信息量，避免"本文介绍了……"这种空泛句式
- 关键要点必须是文章的"硬核内容"，不是章节标题的复述
- 启发部分要体现"读完之后我能做什么"，不是"这篇文章很好"
- 批判性思考要具体指出哪里存疑、为什么存疑
- 延伸思考要指向可继续挖掘的方向，带有行动感

## Pitfalls

- 不要把文章目录当作关键要点——要提炼信息，不是复述结构
- 启发部分最容易写成"这个技术很有前景"式的空话，必须落到具体场景和行动
- 批判性思考不是否定文章，而是标记需要验证的假设和可能的局限
- 如果文章较短（< 500 字），适当精简条目数量，不强凑条数

## Verification

- 报告包含全部 5 个板块（总览、关键要点、启发、批判性思考、延伸思考）
- 启发部分 ≥ 3 条，且每条都关联到用户的关注方向
- 无空泛表述，每个条目都有具体内容支撑
- Markdown 格式正确，可直接渲染
