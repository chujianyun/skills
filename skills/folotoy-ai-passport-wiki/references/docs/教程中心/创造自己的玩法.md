# 创造自己的玩法

跟着官方文档创造玩法，把自己的小游戏和交互真正装进 AI Passport。

<a id="step-1"></a>

## 01 · 先理解产品能力

围绕屏幕、按键、连接与声音等公开能力设计体验。开发前先确认交互目标，以及玩法需要调用的设备能力。

<a id="step-2"></a>

## 02 · 让 AI 编程工具从完整项目开始开发

请使用任意一款 AI 编程工具，例如 Codex、Claude Code 或 TRAE，然后把下面这句话发送到 Agent 的对话框中：

**发送给 Agent 的提示词**

```text
请基于完整项目 https://gitee.com/FoloToy/ai-passport 开发<填写应用需求>；本地已有项目则复用。
先读 AGENTS.md 和 docs/README.md，按需查阅相关文档、硬件接口及示例，自行准备环境并安装项目要求的 Skill。
保留已有修改，新建分支开发。复用 BSP，重新设计应用界面，不照搬 demo；中文界面检查字体覆盖。关键需求不明确时询问，其余自主完成。
运行项目验证，交付可从 0x0 刷写的合并固件，说明测试结果与未验证项。完成后主动询问是否刷机测试，未经确认不烧录。
```

更多玩法请前往 [folotoy/ai-passport↗](<https://github.com/folotoy/ai-passport>) 进行探索。这里提供了 AI Passport 的完整参考项目，不同开发水平的用户都可以通过它学习如何开发新的玩法。

<a id="step-3"></a>

## 03 · 建立可重复的构建流程

把项目依赖、构建步骤和必要配置记录清楚，确保其他开发者也能稳定生成可安装的玩法。

- 记录依赖与构建命令

- 说明必要配置和恢复方式

- 输出玩法版本与构建标识

<a id="step-4"></a>

## 04 · 先在测试设备上验证

先在测试设备上验证自定义玩法的画面、按键和连接功能，并熟悉默认固件的恢复方法。

<a id="step-5"></a>

## 05 · 使用本地玩法安装工具

打开独立的浏览器玩法安装工具，选择按项目说明生成的本地玩法文件。文件完全在当前浏览器读取，不上传服务器。

> **提示**
> 清除设备数据会删除当前配置与用户数据，只有明确需要时才启用。
