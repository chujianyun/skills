# 五视角分析

用五类承担不同责任的角色审视同一个问题。先分别还原各方真实处境，再处理视角之间的冲突，最后形成一个可执行的综合判断。

## 核心原则

- 把五种视角当作交叉检查工具，不要机械凑满五段套话。
- 区分事实、用户提供的信息、合理推断和未知项；不要把假设伪装成事实。
- 关注各角色真正承担的结果、约束和代价，不要只改换措辞重复同一观点。
- 优先寻找视角之间的冲突、隐藏成本和二阶影响；这些通常比共识更有价值。
- 全面不等于平均用力。明确指出当前问题中最关键的一个或两个视角。
- 深度不足时，沿“现象 → 原因 → 机制 → 约束 → 决策”继续追问。

## 工作流

### 1. 界定问题

先提炼：

- 要分析的对象或决策是什么
- 希望改善的结果是什么
- 影响范围和时间尺度是什么
- 已知事实、限制条件和不可改变项是什么

信息不足但仍可稳妥分析时，列出最少必要假设并继续。只有某个缺失信息会实质改变分析方向时，才向用户提出一个最关键的问题。

### 2. 分别分析五种视角

对每个相关角色回答：追求什么、担心什么、受什么约束、会如何判断成败、可能采取什么行动。

| 视角 | 重点检查 |
|---|---|
| 用户 | 真实需求、使用情境、获得的价值、采用阻力、体验与风险 |
| 业务负责人 | 业务结果、优先级、指标、资源投入、机会成本与竞争影响 |
| 一线执行者 | 实际流程、工作负担、可操作性、能力与资源、激励和协作摩擦 |
| 技术负责人 | 可行性、系统质量、架构演进、数据与依赖、安全、维护成本和技术债 |
| 公司经营者 | 战略一致性、商业模式、单位经济性、组织能力、合规声誉和长期选择权 |

某个视角确实不适用时，简要说明原因，不要硬填。分析个人或非商业问题时，按其承担的功能映射角色，例如把“公司经营者”映射为对长期资源和整体结果负责的人。

### 3. 交叉综合

比较五种视角并识别：

- 共识：各方都认可的价值或问题
- 冲突：一方的收益是否由另一方承担成本
- 关键约束：哪个变量决定方案能否成立
- 二阶影响：短期有效的做法会带来什么长期后果
- 可逆性：哪些决定可小步试验，哪些决定代价高且难以撤回
- 盲区：还缺少谁的声音或什么证据

不要用“兼顾所有人”代替取舍。明确说明优先保护什么、暂时牺牲什么，以及理由。

### 4. 形成判断与行动

给出一个明确主判断，并将建议按优先级组织：

1. 现在做：低成本验证关键假设或解除最大约束
2. 接着做：在验证成立后扩大投入或调整方案
3. 暂不做：收益不足、时机不对或风险尚未解除的事项

为关键行动补充可观察的验证信号，让用户能根据结果修正判断。

## 输出契约

默认按以下结构回答；简单问题可以合并章节，但不要省略综合判断：

```markdown
## 问题界定
- 核心问题：
- 关键假设：

## 五种视角
| 视角 | 目标与价值 | 约束与风险 | 关键判断 |
|---|---|---|---|

## 交叉洞察
- 共识：
- 核心冲突：
- 决定性约束：
- 容易忽略的二阶影响：

## 综合判断
用一段话给出取舍明确的结论。

## 行动建议
1. 现在做：
2. 接着做：
3. 暂不做：
```

## 边界与停止条件

- 缺少事实时，输出假设和待验证项，不要编造数据、用户反馈或组织共识。
- 涉及医疗、法律、财务、安全等高风险判断时，把五视角分析作为补充框架，不替代专业意见和必要核验。
- 本技能只负责分析和建议。不要仅凭分析结果执行发布、付款、删除、部署、发消息或其他会改变外部状态的操作。
- 如果真正的利益相关者意见是决策前提，明确建议访谈或调研，不要用角色模拟替代真实反馈。
