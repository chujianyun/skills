# Example data format

> [!TIP]
>
> Before diving into this content, it might be helpful to read the following:
>
> * [Conceptual guide on evaluation](../../Get%20started/Evaluation%20concepts.md)

LangSmith stores examples in datasets as follows:

| Field Name | Type | Description |
| - | - | - |
| **id** | UUID | Unique identifier for the example. |
| **name** | string | The name of the example. |
| **created\_at** | datetime | The time this example was created |
| **modified\_at** | datetime | The last time this example was modified |
| **inputs** | object | A map of inputs for the example. |
| **outputs** | object | A map or set of outputs generated by the run. |
| **dataset\_id** | UUID | The dataset the example belongs to |
| **source\_run\_id** | UUID | For examples created from a LangSmith [`Run`](../../../Monitor/Debug/Data%20type%20reference/Run%20%28span%29%20data%20format.md), the ID of that run |
| **source\_thread\_id** | string | For examples created from a [thread](../../../Monitor/Trace/Observability%20concepts.md#threads) or from a run in a thread, the ID of that thread |
| **metadata** | object | A map of additional, user or SDK defined information that can be stored on an example. |

To learn more about how examples are used in evaluation, read our how-to guide on [evaluating LLM applications](../Run%20an%20evaluation/How%20to%20evaluate%20agents.md).

> [!TIP]
>
> The `outputs` field can also hold [assertions](../../Annotation%20Queues/Use%20assertions.md), free-form claims a reviewer wrote about a correct answer. Offline evaluators read them from `reference_outputs["assertions"]`.
